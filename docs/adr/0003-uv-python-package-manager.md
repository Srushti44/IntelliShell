# ADR 0003: Use uv for Python Package Management

**Status**: Accepted

**Date**: 2024-01-15

## Context

IntelliShell's ai-service component is written in Python 3.13. The prototype used a manual venv setup with an empty `requirements.txt`, which has several issues:

1. **No reproducibility**: `pip install` without lock file installs latest compatible versions (non-deterministic)
2. **Slow installs**: pip downloads and installs packages sequentially
3. **Manual venv management**: Developers must remember to activate venv before running commands
4. **No version pinning**: `requirements.txt` with unpinned versions (`fastapi` instead of `fastapi==0.104.1`)

The team needs a Python package manager that provides:
- **Reproducible installs**: Same versions every time
- **Fast execution**: Minimize CI and local setup time
- **Lock files**: Committed to repo for exact version tracking
- **Modern standards**: PEP 621 (pyproject.toml), PEP 518 (build system)
- **Good developer experience**: Simple commands, automatic venv handling

## Decision

We will use **uv** as the Python package manager for ai-service.

- **Python version pin**: `.python-version` file with `3.13`
- **Dependencies**: Listed in `pyproject.toml` ([project.dependencies])
- **Dev dependencies**: Listed in `pyproject.toml` ([project.optional-dependencies.dev])
- **Lock file**: `uv.lock` committed to repository
- **Installation**: `uv sync` (creates venv, installs exact versions from lock)
- **Running commands**: `uv run <command>` (auto-activates venv)

## Consequences

### Positive

- **10-100x faster than pip**: uv is written in Rust, parallelizes downloads, uses aggressive caching
- **Reproducible installs**: `uv.lock` pins exact versions and hashes
- **Automatic venv management**: `uv run` handles venv activation (no need to remember `source .venv/bin/activate`)
- **Modern Python standards**: Uses pyproject.toml (PEP 621), not legacy setup.py
- **Cross-platform**: Works on Linux, macOS, Windows (important for WSL2 development)
- **Committed lock file**: CI and developers use identical versions

### Negative

- **New tool**: uv is relatively new (released 2023), less mature than pip or poetry
- **Learning curve**: Developers familiar with pip/poetry need to learn new commands
- **Less ecosystem support**: Fewer integrations (though growing rapidly)
- **Potential bugs**: As a newer tool, may have edge cases not seen by millions of users

### Mitigation

- **Document commands**: Add uv commands to Makefile and docs/ENVIRONMENT.md
- **Pin uv version**: Bootstrap script installs specific uv version
- **Fallback to pip**: If uv has critical bugs, migration back to pip is straightforward (uv.lock → requirements.txt conversion)

## Alternatives Considered

### 1. pip + requirements.txt

**Pros**:
- Universal (comes with Python)
- Well-known, mature
- Simple

**Cons**:
- Slow (sequential installs)
- No lock file by default (`pip freeze > requirements.txt` is a manual step)
- Requires manual venv management

**Verdict**: Lacks reproducibility and speed needed for CI.

### 2. Poetry

**Pros**:
- Popular (de facto standard for Python projects)
- Lock file (poetry.lock)
- Dependency resolution
- pyproject.toml support

**Cons**:
- Slower than uv (written in Python, not Rust)
- Complex dependency resolver (can be slow for large projects)
- Heavyweight (many features we don't need, like publishing to PyPI)

**Verdict**: Poetry is good but slower than uv. For a small project like ai-service, uv's speed wins.

### 3. pipenv

**Pros**:
- Lock file (Pipfile.lock)
- Integrated venv management

**Cons**:
- Slow (slower than pip, much slower than uv)
- Pipfile format (not pyproject.toml)
- Declining popularity (many projects migrating away)

**Verdict**: pipenv is outdated; pyproject.toml is the modern standard.

### 4. pdm

**Pros**:
- Fast (uses parallel downloads)
- PEP 621 compliant (pyproject.toml)
- Lock file (pdm.lock)

**Cons**:
- Slower than uv (Python-based)
- Less mature than poetry

**Verdict**: pdm is good but uv is faster (Rust vs Python).

## Migration Plan

1. **Create pyproject.toml** with dependencies:
   ```toml
   [project]
   name = "intellishell-ai-service"
   version = "0.1.0"
   requires-python = ">=3.13"
   dependencies = [
       "fastapi",
       "uvicorn",
       "requests",
       "pydantic",
   ]

   [project.optional-dependencies]
   dev = [
       "pytest",
       "ruff",
   ]
   ```

2. **Create .python-version**: `3.13`

3. **Run `uv sync`**: Generates `uv.lock` with exact versions

4. **Update Makefile**: Replace `python -m pytest` with `uv run pytest`

5. **Update CI**: Replace `pip install -r requirements.txt` with `uv sync`

6. **Delete old files**: Remove `requirements.txt`, `.venv/` (regenerated by uv)

7. **Document**: Update docs/ENVIRONMENT.md with uv installation and usage
